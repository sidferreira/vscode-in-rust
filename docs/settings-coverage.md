## Known differences from VS Code

- Out-of-range numbers are clamped to the schema's minimum and maximum (as `editorOptions.ts` does); a value of the wrong type or outside an enum falls back to the default.
- `workbench.startupEditor` is read once, at startup (as upstream), and only when no editor was restored. `welcomePage` (the default) opens the Welcome page (ADR-0040); `readme` opens the folder's README. `welcomePageInEmptyWorkbench` (rscode always has a folder), `newUntitledFile` opens an empty untitled text (ADR-0058), `terminal` and `agentSessionsWelcomePage` open nothing. The Welcome page's "Show welcome page on startup" checkbox writes this setting.
- Session restore (ADR-0040): the tabs of a folder (order, active, preview), their scroll position and selection, the side bar and the Search query come back when the same folder is opened again. `window.restoreWindows: none` and `workbench.editor.restoreEditors: false` start with nothing restored; with one window, `preserve`, `all`, `folders` and `one` all restore. `workbench.editor.restoreViewState` also restores a file's scroll and selection when it is reopened after being closed in the same run.
- `files.hotExit` (ADR-0040): `onExit` (default) keeps unsaved text in backups when quitting (Cmd+Q) and restores it, dirty, on the next start; closing the window asks (Save All, Don't Save, Cancel). `onExitAndWindowClose` never asks. `off` always asks. Unsaved text is also backed up one second after the last edit (crash safety) and always restored, whatever the restore settings say. `files.restoreUndoStack` is not implemented: undo goes back to the file on disk.
- `window.zoomLevel` scales the editor text only (1.2 per level, as upstream). The title bar, side bars and tabs keep their pixel sizes until the UI has a whole-window scale (ADR-0035).
- `editor.cursorBlinking`: `smooth`, `phase` and `expand` blink like `blink`; `solid` does not blink.
- `editor.lineNumbers: interval` shows a number on every 10th line and on the caret line.
- `files.exclude` merges with the default (object settings deep-merge, as `mergeContents`) and supports `true`/`false` and `when` with `$(basename)`; patterns are matched against the path relative to the opened folder.
- `workbench.activityBar.location: top` and `bottom` show the view icons as a horizontal strip in the side bar (no title bar integration).
- Find widget: regular expressions use Rust `regex` syntax (no look-around or backreferences, as in the Search view); Whole Word uses `\b` rather than `editor.wordSeparators`; there is one cursor, so no "Select All Occurrences of Find Match". `editor.find.addExtraSpaceOnTop` is not implemented (see `upstream/settings.toml`).
- `editor.detectIndentation` is not implemented: `editor.tabSize` and `editor.insertSpaces` always apply.
- Search reads `files.exclude` too (it is listed under Explorer). Entries of `search.exclude` and `files.exclude` whose value is an object (`when` clauses) are ignored by the search.
- `workbench.editor.enablePreviewFromCodeNavigation` is read by the Outline's click (ADR-0092), the only code navigation rscode has so far; go to definition is not implemented.
- `search.sortOrder` orders the files of the current results and places the files of later searches by the same order. `modified` reads each file's modification time when it is found.
- `search.seedOnFocus` and `search.seedWithNearestWord` apply when the Search view is focused with Find in Files (Shift+Cmd+F). Other ways of showing the view do not seed the query.
- `search.ripgrep.maxThreads` sets the walker threads of a search (0 is automatic).
- `explorer.excludeGitIgnore` reads the `.gitignore` files from the workspace root down to each listed folder. A change to a `.gitignore` shows when its folder is listed again (there is no watch on `.gitignore` files yet). The global gitignore and `.git/info/exclude` are not read.
- `explorer.copyPathSeparator` and `explorer.copyRelativePathSeparator` apply to Copy Path (Alt+Cmd+C) and Copy Relative Path (Shift+Alt+Cmd+C), which copy the selected entry or else the active editor's file. The Explorer has no context menu yet, so the two are Command Palette entries and keys.
- Editor groups: rscode has one group. `limit.*` counts the whole group, `revealIfOpen` and `focusRecentEditorAfterClose` apply to that group's tabs. `limit.perEditorGroup` is not read.
- `explorer.sortOrder: foldersNestsFiles` sorts like `default`: rscode has no file nesting (`explorer.fileNesting.*`), so nothing is nested. Names sort case-insensitively with numbers in order (`file2` before `file10`).
- `explorer.autoReveal` runs when an editor opens. Switching tabs does not reveal the file yet. The scroll is a request to the tree's scroll handle; the headless tests cannot observe it.
- `explorer.confirmDelete` covers Delete (Trash, or permanent when `files.enableTrash` is off) and Delete Permanently. Dirty editors are not asked about: they stay open with their text.
- `workbench.editor.labelFormat: long` shows the directory's absolute path; `default` adds the directory (relative to the folder) only to tabs that share a name.
- `workbench.editor.highlightModifiedTabs` always uses the focused-group colours (`tab.activeModifiedBorder`, `tab.inactiveModifiedBorder`).
- `workbench.editor.closeOnFileDelete` checks that files exist once a second (no file watcher yet). Editors with unsaved changes stay open.
- `files.eol` applies to a text that has no line break yet (an opened one-line file). A file with line breaks keeps its own. A new untitled text has no line break yet, so it takes the setting too.
- `files.autoSave: onFocusChange` saves when the active editor changes and when the window loses focus. Focus moving between the editor and other views does not save (no focus tracking of the editor surface yet). `autoSaveWhenNoErrors` is not wired (no diagnostics).
- `files.readonly*` and the toggle `workbench.action.files.toggleActiveEditorReadonlyInSession` refuse edits in the editor, in Find/Replace and in Search's Replace. A read-only tab shows a lock. Saving a read-only file is still allowed.
- Languages and syntax highlighting (ADR-0038): the language of a file comes from `files.associations`, then the built-in language contributions (file names, extensions, first line), else Plain Text. The bundled TextMate grammars (Rust, JavaScript/TypeScript (+ JSX/TSX), JSON/JSONC, Markdown, Python, Shell, CSS, HTML, YAML, XML/XSL, C/C++/CUDA, Go, Java) colour tokens with the active theme's token colors; other languages show plain. `files.defaultLanguage` is the language of a new untitled text (`${activeEditorLanguage}` is the active editor's language); the language of an untitled text can be changed afterwards, and Save As detects it from the new name (ADR-0058, ADR-0059). `editor.maxTokenizationLineLength` re-tokenizes live. `files.trimTrailingWhitespaceInRegexAndStrings: false` keeps trailing whitespace inside strings and regular expressions, and in lines the tokenizer has not reached yet.
- Word wrap: `editor.wrappingStrategy: advanced` breaks like `simple` (the monospace computer; the advanced strategy measures text in the browser). `editor.wordWrapIndicator` draws a return arrow after the last column of a row that continues. Alt+Z wraps at the viewport width or turns wrapping off for that editor only (it does not write the setting). `editor.wordSeparators` drives word moves, double-click and the whole-word check of selection highlights; the Find widget still uses `\b`, and the word at the caret for occurrence highlights uses the default separators (upstream: the language's word definition). `editor.wordSegmenterLocales` (CJK word segmentation) is not implemented.
- Themes (ADR-0037): the ten built-in themes of VS Code (Dark Modern, Light Modern, Dark+, Light+, Dark (Visual Studio), Light (Visual Studio), Dark High Contrast, Light High Contrast, Dark 2026, Light 2026) are bundled; other names in the `workbench.colorTheme` dropdown (Abyss, Monokai, ...) belong to extensions rscode has not got and fall back to the default theme of that colour mode. The default dark theme is Dark 2026 as upstream (ADR-0049); the default light theme is still Light Modern, not Light 2026 as upstream.
- `workbench.preferred*ColorTheme` apply with `window.autoDetectColorScheme`, which follows the window appearance (macOS light/dark). `window.autoDetectHighContrast` and `workbench.preferredHighContrast*ColorTheme` are not wired: there is no OS high contrast signal in gpui. `workbench.colorCustomizations` supports global keys and `[Theme Name]` blocks (with `*` wildcards) and the value `default`; `editor.tokenColorCustomizations` (the simple keys and `textMateRules`, global and `[Theme Name]`) apply to the syntax highlighter's token colours (ADR-0038). `editor.semanticTokenColorCustomizations` is read by the theme service but changes nothing on screen (there are no semantic tokens yet). Icon themes stay unsupported (no file icons).
- Caret (ADR-0043): `editor.cursorHeight` centres the line caret (`line` and `line-thin` only). `editor.cursorSurroundingLines` keeps the margin when the caret scrolls into view: the top margin is the setting, the bottom one is at least one row (upstream's "trailing lines (minimum 1)"), each capped at half the page. With `cursorSurroundingLinesStyle: default` a click does not enforce it. `cursorSmoothCaretAnimation` is not implemented (the caret jumps).
- Rendering (ADR-0043): `editor.renderControlCharacters` draws the C0 controls (but tab) and DEL as Control Pictures (U+2400 block) over a cell; the bidi formatting characters are not drawn. `editor.renderFinalNewline: dimmed` dims the number at half opacity.
- `editor.tabFocusMode`: Tab moves focus instead of typing a tab, but rscode has no focus tab stops outside the editor yet, so the focus stays in the editor. The Ctrl+Shift+M toggle is not implemented.
- Not wired (blocked, see `upstream/settings.toml`): `mouseWheelZoom` and `mouseWheelScrollSensitivity` need a scroll capture on the editor surface; `guides.bracketPairs`, `bracketPairsHorizontal` and `highlightActiveBracketPair` need a whole-document bracket pair model; `fontVariations` needs font variation axes; `mouseMiddleClickAction` needs ctrl+click and links; `editor.format*` need formatting providers.
