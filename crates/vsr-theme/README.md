# vsr-theme

The data side of rscode's theme service, free of any UI (ADR-0037): VS Code colour themes loaded
from their JSON (JSONC, `include` chains, `colors`, `tokenColors`, `semanticTokenColors`), the
colour registry defaults, `workbench.colorCustomizations` / `editor.tokenColorCustomizations`
(global and per `[Theme Name]` block), and the choice of the active theme from the settings and the
system appearance. `vsr-app` turns a [`ColorTheme`] into painted colours; the syntax highlighter
reads [`ColorTheme::token_colors`] (raw textmate rules, no scope matching here).

## Bundled data and where it comes from

| file | what | source |
|---|---|---|
| `assets/themes/*.json` | the ten themes of the built-in `theme-defaults` extension: Dark Modern, Light Modern, Dark+, Light+, Dark (Visual Studio), Light (Visual Studio), Dark High Contrast, Light High Contrast, Dark 2026, Light 2026 | `extensions/theme-defaults/themes/` @ `50e1350fc78d` (VS Code 1.147.0), copied unchanged. MIT, Copyright (c) 2015 - present Microsoft Corporation (`assets/themes/LICENSE.txt`). |
| `assets/color-defaults.json` | the default of every colour key (611) for dark, light, high contrast dark and high contrast light themes, as expression trees (`transparent`, `lighten`, `oneOf`, ...) | generated by `scripts/gen-color-defaults` from the `registerColor(...)` calls of `src/vs/platform/theme/common/colors/*.ts`, `src/vs/workbench/common/theme.ts`, `editorColorRegistry.ts`, `settingsEditorColorRegistry.ts` and a few editor contributions @ `50e1350fc78d` |

The theme ids, labels and `uiTheme` values in `src/catalog.rs` are `extensions/theme-defaults/package.json`
and `package.nls.json`.

Regenerate the colour table (the parser fails on any TypeScript construct it does not know, instead
of dropping a colour):

```sh
python3 -I scripts/gen-color-defaults --clone ../vscode-original
python3 -I scripts/gen-color-defaults --clone ../vscode-original --check   # CI-style staleness check
```

## API in one paragraph

`ThemeCatalog::builtin()` lists the themes (`ThemeContribution`: settings id, label, `uiTheme`);
`catalog.load(..)` returns a `ColorTheme`. `theme.color("editor.background")` is the customisation,
else the theme's colour, else the registry default for the theme type (`ColorScheme`).
`theme.with_customizations(&Customizations { .. })` applies the user's settings.
`ThemeSettings::resolve(&catalog, HostColorScheme)` picks the theme for `workbench.colorTheme`,
the `workbench.preferred*ColorTheme` settings and the system appearance.
`theme.token_colors() -> &[TokenColorRule]` (scope selector strings + `{ foreground, background,
fontStyle }`) and `theme.semantic_token_rules()` are for the highlighter.

## Differences from VS Code

- Default dark theme is Dark 2026, as upstream 1.147 (ADR-0049); preferred defaults follow (ADR-0037).
- tmTheme (plist) token colour files are not supported (all bundled themes are JSON).
- `Color.fromHex` falls back to red for a malformed colour, as upstream; the app's `hex()` for
  user-typed colours is strict and returns `None`.
- No theme storage, transient colours or token style resolution (`getTokenStyle`).
